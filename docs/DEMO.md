# ExperienceOS 演示剧本

> 面向 HR / 技术面试官的现场演示脚本。目标：3 分钟内讲清「这是什么、
> 为什么不同、工程上怎么做」。全程可离线，无网络依赖。

---

## 30 秒电梯稿（对 HR）

> "我做了一个开源项目叫 ExperienceOS——个人经历操作系统。开发者做过很多
> 项目，几年后细节全忘了，面试时临时抱佛脚。它把 GitHub、本地代码、旧简历
> 这些碎片自动整理成**有证据支撑**的经历资产：每个成果都挂着仓库、commit
> 或文档作为证据。它刻意**不是简历生成器**——不包装、不编造，AI 只做整理
> 提案，人确认后才入库，数据全部存在本地。"

三个关键词：**证据支撑、本地优先、AI 只提案**。

---

## 3 分钟现场演示分镜

### 准备清单（演示前 10 分钟）

- [ ] `git pull` 确认最新；`pip install -e .` 已装好
- [ ] `experienceos web --port 8420` 已启动，浏览器已打开 http://127.0.0.1:8420
- [ ] 工作台处于演示模式（默认），页面显示 3 条示例经历
- [ ] 备用：录屏视频（见 README），现场失败时直接放视频

### 分镜 1：离线演示（60 秒）——「AI 不能凭空作答」

1. 指着侧栏：「3 条**合成**示例经历，数据明确标注来自 `ai:synthetic-demo`」
2. 点击「运行」→ 旁白：「模型要回答问题，必须先调用三个只读工具——
   检索、逐条读取、证据统计」，指着运行记录时间线逐条念
3. 简报出现后，指「来源 3」：「每条结论都带引用，引用的位置必须是本次
   运行中真实读到的证据位置——引用不接地，工作流直接判暂停，**不给幻觉
   输出的机会**」
4. 指「缺口」：「注意它诚实地指出有一条记录没有证据——系统鼓励补证据，
   而不是编成果」

### 分镜 2：中断恢复（45 秒）——「工程化处理失败」

1. 勾选「中断演示」，再点「运行」
2. 「我们模拟模型在工具调用后中断——真实世界网络就是会断」
3. 状态变「已暂停」后点「继续运行」→「从保存的检查点精确恢复，已完成的
   工具调用不会重跑」
4. 旁白：「每轮对话都是原子化的 JSON 检查点，这就是把 LLM 应用当软件
   工程做」

### 分镜 3：工程深度（45 秒）——「不靠感觉，靠评测」

1. 打开终端跑 `experienceos ai eval`
2. 指着输出：「9 条带标签的评测用例：工具调用序列、schema 合法性、引用
   接地、错误恢复，全部断言化。现在 9/9 全过——AI 质量有回归测试」
3. 收尾：「448 个测试、三平台 CI 矩阵、wheel 打包在仓库外验证安装，
   依赖方向由 AST 守卫测试强制。**我把 LLM 应用当成正经软件系统来做**」

## 兜底预案

| 风险 | 预案 |
| --- | --- |
| 端口被占（默认 8765 被百度输入法占用过） | `experienceos web --port 8420` |
| 演示模式跑不了 | 放录屏；或跑 `python examples/agent_demo.py --home .experienceos-demo`（纯命令行演示） |
| 被问真实模型效果 | 如实说：评测集是确定性回归，`--live` 可跑真模型；诚实声明数字不代表模型准确率——这本身就是项目「不夸大」理念的体现 |
| 断网 | 全程不依赖网络：演示模式离线，`ai eval` 回放离线 |

## CTO 深度问答预案（5 个必然被问的问题）

**Q1：为什么本地 JSON 文件 + 可选 SQLite FTS，不用 Postgres？**

> 这是个人知识库，单用户、单机、数据量千条级。纯 JSON 文件是人可读的
> source of truth，用户可以自己 git 化、自己备份、随时拿走——这是
> local-first 产品理念的一部分，不是技术偷懒。FTS5 索引是可重建的加速层，
> 超过阈值才启用，小库直接内存扫描反而更快。正确性归文件，性能归索引，
> 两层各司其职。

**Q2：AI 幻觉怎么防？**

> 三道闸：第一，工具前置——模型必须先读真实记录才能作答；第二，**引用
> 接地校验**——输出里每个引用的 evidence_location 必须是本次运行中实际
> 读取到的，对不上就判暂停，workflow 层直接拒绝输出；第三，`ai eval`
> 评测集把「拒绝虚构位置」做成断言用例（`reject_invented_location`），
> 防回归。另外所有 AI 写入都是 draft，人工确认才转正。

**Q3：AI 质量怎么度量？**

> 9 条带标签用例 + 确定性回放 provider：同一份录制回合可以无限次重放，
> 断言工具调用序列、结构化输出合法性、引用接地、期望内容和错误恢复五类
> 行为。这是回归测试，不是模型准确率声明——manifest 里用 sha256 固定
> 数据集并明确写了 not-valid-for。`--live` 支持同一数据集跑真实模型。

**Q4：隐私模型是什么？**

> 数据永不离开本机：JSON 文件在 `~/.experienceos/`，API key 只从环境变量
> 读取、绝不入 checkpoint 或报告。AI 运行报告默认脱敏——只有延迟、token、
> 重试这类运营指标，没有 prompt 和个人内容；web 端错误统一脱敏文案，
> 原始异常不出网；不记录访问日志。web 服务有 Host/Origin/Sec-Fetch-Site
> 校验和严格 CSP，只绑 127.0.0.1。

**Q5：为什么 API 是只读的、写入只在 CLI？**

> 确认性写操作（draft→active、编辑、删除）是这个产品的信任边界。CLI 是
> 人在环上的交互面，web/API 是浏览和分析面。API 只开放只读查询和创建
> draft——机器可以贡献，但不能替你确认。
