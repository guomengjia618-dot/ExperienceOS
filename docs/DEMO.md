# ExperienceOS 演示剧本(v2,对应 v0.7.3)

> 面向 HR / 技术面试官的现场演示脚本。目标:3 分钟讲清「这是什么、
> 为什么不同」,8 分钟讲透「工程上怎么做」。全程可离线兜底,
> 每个可点击的数字都是活的。

---

## 30 秒电梯稿(对 HR)

> "我做了一个开源项目叫 ExperienceOS——个人经历操作系统。开发者做过很多
> 项目,几年后细节全忘了,面试时临时抱佛脚。它把 GitHub、本地代码、旧简历
> 这些碎片自动整理成**有证据支撑**的经历资产:每个成果都挂着仓库、commit
> 或文档作为证据。它刻意**不是简历生成器**——不包装、不编造,AI 只做整理
> 提案,人确认后才入库,数据全部存在本地。"

三个关键词:**证据支撑、本地优先、AI 只提案**。

## 分镜 A:离线工作台(60 秒)——「AI 不能凭空作答」

1. 指着侧栏:「3 条**合成**示例经历,数据明确标注来自 `ai:synthetic-demo`」
2. 点击「运行」→ 旁白:「模型要回答问题,必须先调用三个只读工具——
   检索、逐条读取、证据统计」,指着运行记录时间线逐条念
3. 简报出现后,指「来源」:「每条结论都带引用,引用的位置必须是本次
   运行中真实读到的证据位置——引用不接地,工作流直接判暂停,**不给
   幻觉输出的机会**」
4. 指「缺口」:「注意它诚实地指出有一条记录没有证据——系统鼓励补证据,
   而不是编成果」

## CTO 深度问答预案(8 个高频问题)

**Q1:为什么本地 JSON 文件 + 可选 SQLite FTS,不用 Postgres?**

> 单用户、单机、千条级数据。纯 JSON 是人可读的 source of truth,用户可以
> 自己 git 化、随时拿走——这是 local-first 产品理念,不是技术偷懒。FTS5
> 是可重建的加速层,带 busy_timeout 和陈旧自动重建;正确性归文件,性能
> 归索引。写入有跨进程文件锁 + fsync 原子替换,CLI/API/工作台可以并存。

**Q2:AI 幻觉怎么防?**

> 四道闸:①工具前置——必须先读真实记录;②引用接地校验——每个引用
> 必须是本次运行真实读过的证据位置,违者暂停;③AI 写入一律 draft,
> 人工确认才转正;④评测集把「拒绝虚构位置」做成断言用例防回归。

**Q3:AI 质量怎么度量?**

> 双轨:录制回放是**精确回归**(工具序列全等、全部术语、sha256 manifest
> 固定数据集);live 是**冒烟语义**(工具覆盖、实质内容任一命中),两者
> 分开报告、声明不可用于准确率宣传。checkpoint 和报告记录 prompt 版本,
> 评测可归因。

**Q4:隐私模型是什么?**

> 数据永不离开本机;API key 只从环境变量读取,绝不入 checkpoint/报告/
> 配置文件;运行报告默认脱敏(只有延迟、token、prompt 版本);web 只绑
> 127.0.0.1,带 Host/Origin 校验和严格 CSP,不记访问日志。SECURITY.md
> 里写了完整威胁模型和"不在边界内"的诚实声明。

**Q5:多少代码是 AI 写的?**

> 如实说:AI 深度参与编码,但架构决策、评审标准、测试纪律是我的。证据
> 是可验证的:规范提交历史、448 个测试、AST 分层守卫、9 用例评测集、
> 三个版本的真实发布流水线。**我把它当软件工程做,AI 是我的工程杠杆——
> 这个项目本身就是这个方法论的活证明。**

**Q6:live 8/9 怎么理解?剩下 1/9 是失败吗?**

> 是真发现,不是故障。那个用例里模型连搜 11 次都不加载记录就作答——
> 系统护栏拒绝了不接地的引用,但无法强迫模型读档。我选择如实写在
> README 而不是调宽断言,因为这正是评测该暴露的。这也演示了"录制精确
> 回归"和"live 冒烟"两种断言语义为什么必须分开。

**Q7:覆盖率 90%,另外 10% 是什么?**

> 主要是 web 前端静态资源和 Windows/POSIX 平台分支的防御性代码
> (目录 fsync、锁的超时兜底)。核心路径——存储原子写、工作流、
> 接地校验、迁移——接近全覆盖。CI 有 80% 硬门槛。

**Q8:为什么 API 只读、写入只在 CLI?**

> 确认性写操作(draft→active)是产品的信任边界。CLI 是人在环上的
> 交互面,API/工作台是浏览分析面。机器可以贡献 draft,但不能替你确认。

## 兜底预案

| 风险 | 预案 |
| --- | --- |
| 8420 端口被占 | `experienceos web --port 8430` |
